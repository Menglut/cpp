# CppStudy 테스트 체크리스트

최근 갱신: 2026-09-29  
기준 환경: Windows, Node.js 24 이상, npm 11 이상, Docker Desktop

## 1. 테스트 전 준비

- [ ] `docker info`가 오류 없이 실행된다.
- [ ] `npm.cmd ci` 또는 `npm.cmd install`을 완료했다.
- [ ] 루트 `.env`의 `DATABASE_URL`, `REDIS_URL`, `WEB_ORIGIN`을 확인했다.
- [ ] Judge0 시험 시 SSH 터널 `127.0.0.1:2358`을 열었다.
- [ ] Judge0 시험 시 `EXECUTION_PROVIDER=judge0`과 인증 토큰을 설정했다.
- [ ] 오프라인 흐름 시험 시 `EXECUTION_PROVIDER=fake`를 설정했다.

```powershell
npm.cmd run infra:up
npm.cmd run prisma:deploy
npm.cmd run prisma:seed
npm.cmd run infra:status
```

API, Worker, Web은 서로 다른 터미널에서 실행한다.

```powershell
npm.cmd run dev:api
npm.cmd run dev:worker
npm.cmd run dev:web
```

## 2. 빠른 자동 검증

- [ ] 전체 TypeScript 검사를 통과한다.
- [ ] 단위 테스트를 통과한다.
- [ ] 프로덕션 빌드를 통과한다.
- [ ] 관리자 API 통합 테스트를 통과한다.

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run test:admin-integration
```

`test:admin-integration`은 임시 관리자·강의·문제를 생성하고 다음 흐름을 확인한다.

- 관리자 콘텐츠 목록 조회
- 학습 카테고리 생성·공개와 카테고리별 강의 그룹 조회
- 카테고리 보관 시 소속 공개 강의 숨김
- 이미지 업로드, 공개 조회, 관리자 목록 조회와 삭제
- 강의 생성, 기존 공개 버전 유지와 새 버전 공개
- 문제, 공개 예제, 숨김 테스트, 강의·카테고리 연결 저장
- 기준 코드 Queue 처리와 실행 Provider 검증
- 문제 공개 후 공개 API 조회
- 문제 보관 및 복원
- 생성한 테스트 데이터 자동 삭제

실패한 경우에도 `finally` 단계에서 테스트 데이터를 정리한다. 프로세스가 강제 종료되어 데이터가 남았다면 `admin-integration-` 이메일과 `integration-` slug를 기준으로 확인한 후 삭제한다.

## 3. 단위 테스트 체크리스트

### API

- [ ] 환경변수 누락 시 시작을 거절한다.
- [ ] 잘못된 `WEB_ORIGIN`을 거절한다.
- [ ] 세션 쿠키와 CSRF 정책이 예상 값으로 생성된다.
- [ ] 일반 사용자의 관리자 API 접근이 `403`이다.
- [ ] 미인증 관리자 API 접근이 `401`이다.
- [ ] 공개된 문제 버전 수정이 `409`다.
- [ ] 검증되지 않은 문제 공개가 `409`다.
- [ ] 공개 예제 1개·숨김 테스트 3개 미만이면 검증 요청이 `409`다.

### Judge Worker

- [ ] Fake Provider의 SUCCESS/WA/CE/RE/TLE/MLE/OLE/SYSTEM_ERROR를 확인한다.
- [ ] Judge0 비동기 생성·폴링·Base64 해제를 확인한다.
- [ ] Judge0 컴파일 오류를 CE로 변환한다.
- [ ] 기준 코드 출력 일치 시 검증 상태가 `PASSED`다.
- [ ] 기준 코드 출력 불일치 시 검증 상태가 `FAILED`다.
- [ ] 검증 성공 시 문제 버전의 `validatedAt`이 설정된다.
- [ ] 이미 완료된 검증 작업을 다시 처리해도 결과가 중복되지 않는다.

### 출력 비교기

- [ ] TOKEN 비교에서 연속 공백과 줄바꿈 차이를 허용한다.
- [ ] TOKEN 비교에서 추가 토큰을 거절한다.
- [ ] EXACT 비교에서 본문 차이를 거절한다.
- [ ] `allowFinalNewline` 설정에 따른 마지막 줄바꿈을 확인한다.

## 4. 관리자 브라우저 통합 테스트

### 권한과 조회

- [ ] 비로그인 상태에서 `/admin` 진입 시 로그인을 안내한다.
- [ ] 일반 사용자에게 관리자 화면을 표시하지 않는다.
- [ ] 관리자 로그인 후 서버의 강의·문제 목록을 표시한다.
- [ ] 공개 문제 상세에서도 숨김 테스트가 일반 `/problems/:number` 응답에 없다.
- [ ] 관리자 상세 응답에서만 숨김 테스트와 기준 코드를 조회한다.

### 강의

- [ ] 새 강의를 DRAFT로 저장한다.
- [ ] 제목·요약·본문·순서와 연결 문제를 수정한다.
- [ ] 새로고침 후 저장한 값이 유지된다.
- [ ] 강의를 공개하면 `/learn` 목록에 나타난다.
- [ ] 강의를 보관하면 공개 목록에서 사라진다.
- [ ] 보관한 강의를 복원하면 이전 공개 상태로 돌아간다.
- [ ] 공개 강의를 편집해 저장하면 새 초안 버전이 자동 생성된다.
- [ ] 새 버전 공개 전에는 기존 본문이 계속 제공된다.
- [ ] 표, 이미지 캡션, C++ 코드 강조·복사, 콜아웃과 자동 목차가 표시된다.
- [ ] 학습 목록이 `1. 카테고리 → 1.1 세부 강의` 구조로 표시된다.
- [ ] 강의 편집에서 소속 카테고리와 카테고리 내부 순서를 변경할 수 있다.
- [ ] 카테고리를 보관하면 소속 강의가 공개 목록과 상세에서 숨겨진다.

### 학습 카테고리

- [ ] 카테고리 slug, 이름, 소개와 표시 순서를 생성·수정하고 중복 slug를 거절한다.
- [ ] 초안 카테고리는 공개 학습 목록에 표시하지 않는다.
- [ ] 공개·보관·복원이 공개 목록에 반영된다.
- [ ] 카테고리와 내부 강의 순서로 `1.1` 번호가 자동 계산된다.

### 미디어

- [ ] PNG/JPEG/GIF/WebP 이미지를 5MB 이하로 업로드한다.
- [ ] 확장자와 MIME을 속인 파일 및 SVG 업로드를 거절한다.
- [ ] 업로드한 이미지의 Markdown 문법을 복사해 강의 미리보기에서 확인한다.
- [ ] 이미지 공개 URL은 인증 없이 표시되고 `nosniff`와 장기 캐시 헤더를 제공한다.
- [ ] 이미지를 삭제하면 관리자 목록과 파일 저장소에서 제거된다.

### 문제

- [ ] 문제 번호·제목·난이도·본문·제한을 저장한다.
- [ ] 카테고리와 연결 강의를 저장한다.
- [ ] 공개 예제와 숨김 테스트를 저장한다.
- [ ] 메모리 MiB 값이 API에서 KiB로 정확히 변환된다.
- [ ] 기준 코드가 없으면 검증을 시작하지 못한다.
- [ ] 공개 예제 1개와 숨김 테스트 3개 미만이면 검증을 거절한다.
- [ ] 검증 중 `PENDING` 또는 `RUNNING` 상태를 표시한다.
- [ ] 검증 성공 후 공개 버튼이 활성화된다.
- [ ] 검증 실패 진단을 관리자에게 표시하되 숨김 입출력은 표시하지 않는다.
- [ ] 공개 후 일반 문제 목록과 상세에서 조회된다.
- [ ] 공개 버전은 직접 수정할 수 없다.
- [ ] 새 버전 만들기로 공개 버전을 복사해 편집할 수 있다.
- [ ] 새 버전 공개 전에는 기존 공개 버전이 계속 제공된다.
- [ ] 보관과 복원이 공개 목록에 반영된다.

## 5. 인증·사용자 통합 테스트

- [ ] 회원가입 후 HttpOnly 세션 쿠키가 발급된다.
- [ ] 로그인 성공 시 기존 세션을 재사용하지 않고 새 세션을 발급한다.
- [ ] 로그아웃 후 인증 API가 `401`을 반환한다.
- [ ] CSRF 헤더가 없거나 쿠키와 다르면 변경 요청을 거절한다.
- [ ] 허용되지 않은 Origin의 변경 요청을 거절한다.
- [ ] 세션 만료 중 편집 화면이 로그인 안내로 전환된다.
- [ ] 다른 사용자의 제출 상세 조회가 `404` 또는 `403`이다.
- [ ] 일반 사용자의 `/admin/*` 요청이 모두 `403`이다.

## 6. 실행·제출 통합 테스트

- [ ] 실행 요청이 DB에 PENDING으로 생성된다.
- [ ] Outbox가 BullMQ에 전달한 뒤 QUEUED로 바뀐다.
- [ ] Worker가 RUNNING과 최종 상태를 기록한다.
- [ ] 실행 결과 폴링이 최종 상태에서 중단된다.
- [ ] 공식 제출은 동일 Idempotency-Key와 동일 본문에서 같은 제출을 반환한다.
- [ ] 동일 Idempotency-Key에 다른 본문을 보내면 `409`다.
- [ ] AC 후 WA를 제출해도 해결 상태가 유지된다.
- [ ] SYSTEM_ERROR와 대기 상태는 오답 시도로 집계하지 않는다.
- [ ] 제출 상세에 당시 소스와 문제 버전이 고정된다.
- [ ] 숨김 입력·기대 출력·실제 출력이 사용자 응답에 포함되지 않는다.

## 7. Judge0 판정 검증

아래 fixture는 운영 데이터가 없는 전용 Judge0 환경에서 실행한다.

| 판정         | 테스트 코드 특성                    | 기대 결과                     | 완료 |
| ------------ | ----------------------------------- | ----------------------------- | ---- |
| AC           | 모든 테스트에 정확한 출력           | `AC`                          | [ ]  |
| WA           | 한 테스트에서 다른 출력             | `WA`                          | [ ]  |
| CE           | 문법 오류                           | `CE`                          | [ ]  |
| RE           | 잘못된 메모리 접근 또는 비정상 종료 | `RE`                          | [ ]  |
| TLE          | 무한 루프                           | `TLE`                         | [ ]  |
| MLE          | 제한 이상의 메모리 할당             | `MLE` 또는 문서화된 식별 한계 | [ ]  |
| OLE          | 제한 이상의 출력 생성               | `OLE` 또는 문서화된 식별 한계 | [ ]  |
| SYSTEM_ERROR | Judge0 연결 중단                    | `SYSTEM_ERROR`                | [ ]  |

- [ ] Judge0 `/about`의 버전이 문서와 일치한다.
- [ ] C++17 language ID와 실제 GCC 버전을 기록한다.
- [ ] CPU 시간 제한 단위가 ms→초로 정확히 변환된다.
- [ ] 메모리 제한 단위가 KiB로 정확히 전달된다.
- [ ] `enable_network=false`가 적용된다.
- [ ] 내부망, 메타데이터 주소와 인터넷 접근이 차단된다.
- [ ] 무한 루프 종료 후 다음 작업을 정상 처리한다.
- [ ] 출력 폭주가 Worker와 호스트 전체 장애로 이어지지 않는다.

## 8. 장애 복구와 동시성

- [ ] Redis 중단 중 생성한 Outbox 이벤트가 DB에 남는다.
- [ ] Redis 복구 후 이벤트가 Queue에 한 번 이상 전달된다.
- [ ] 같은 Outbox 이벤트 재전달이 결과를 중복 집계하지 않는다.
- [ ] Worker 처리 도중 종료 후 작업을 재처리한다.
- [ ] 다중 Worker가 같은 제출을 동시에 최종 처리하지 않는다.
- [ ] Judge0 요청 타임아웃이 SYSTEM_ERROR로 정리된다.
- [ ] API 재시작 후 기존 제출 상태를 계속 조회할 수 있다.
